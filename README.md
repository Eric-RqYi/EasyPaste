# EasyPaste

将 PDF、网页或图片中的内容整理为 Obsidian Markdown / LaTeX。所有修改先预览、确认后写入；自动粘贴仅运行离线规则。

## 安装

要求 **Obsidian 1.11.4+**。

1. 将安装包中的 `easy-paste` 文件夹放入笔记库的 `.obsidian/plugins/`。
2. 确认 `.obsidian/plugins/easy-paste/` 下直接包含 `main.js`、`manifest.json`、`styles.css`。
3. 在 Obsidian → 设置 → 第三方插件中启用 EasyPaste。
4. 若使用 LLM/OCR，在 EasyPaste 设置的「智能转换」和「图片转换」分区分别填写 Base URL、API Key 和 Model Name。离线规则不需要密钥。

## 使用

| 入口 | 操作 |
| --- | --- |
| 自动粘贴 | 检测到规则可修复的文本时弹出预览；点击「确认应用」粘贴转换结果，或「粘贴原文」。取消或 Esc 不插入内容。 |
| 编辑器右键 | 使用「智能转换」处理文本或图片；「离线清洗」仍用于选中文本的本地规则处理。 |
| 快捷键 / 命令面板 | 在设置 → 快捷键中搜索 `EasyPaste`，绑定「离线清洗」或「智能转换」。插件默认不占用按键；插件设置可关闭这些命令。 |
| 智能转换 | 选中纯文本时使用文本 API；选区包含图片时使用视觉 API，同时发送选区文本。无选区时，在同一窗口粘贴文本、粘贴图片或添加图片文件，确认后插入原光标处。 |
| 图片右键 | 在文件列表中右键图片，使用「EasyPaste：智能转换」打开同一窗口。 |

智能转换窗口支持修改待转换文本、添加多张图片和移除添加的图片，并实时显示将使用的 API 地址与模型。支持选区内的 `![[image.png]]` / `![](image.png)` 图片嵌入（包括文字与多张图片混合）；HTTPS 图片链接直接交给视觉 API。代码示例中的图片语法不作为图片上传。找不到本地图片时提示错误，不会改用文本 API。

智能转换窗口点击「发送并转换」才发出请求；规则预览窗口则点击「使用 LLM 智能转换」。修改输入或增删图片后，需要重新转换才能确认应用。原「图片 OCR」命令已合并到「智能转换」，此前绑定到图片命令的快捷键需重新绑定；原文本转换命令的快捷键继续有效。

预览只保留「差异 / 预览」两个视图，均支持编辑，长文本自动换行：

- **差异**：左侧显示只读原文（红色删除线），右侧直接编辑转换结果（绿色表示新增），编辑后更新差异高亮。
- **预览**：左侧编辑 Markdown，右侧实时渲染排版与公式；切换视图保留同一份编辑内容。

规则转换窗口底部的「使用 LLM 智能转换」会将**原始粘贴或选中内容**发送给所配置的智能转换 API，在同一窗口展示结果，不会自动写入笔记。手动「离线清洗」即使没有检测到变化，也会打开预览，方便调整规则或使用 LLM。

展示区右上方的「配置规则」可展开右侧面板，快速开关内置/自定义规则，拖动每条规则左侧的三横杠调整顺序，也可使用上下箭头或聚焦手柄后按方向键排序。面板不能新增、编辑或删除规则；底部齿轮按钮打开设置中的离线规则配置。开关与顺序立即保存，预览从原文重新计算（会覆盖手动编辑），从完整设置中修改规则也会同步更新。请求 LLM 期间暂时锁定规则列表。

### 自动预览的明确触发条件

自动粘贴预览默认开启，同时满足以下条件才拦截粘贴：

- 事件尚未被其他插件处理，编辑器中没有未完成的 EasyPaste 弹窗。
- 剪贴板有纯文本，且不含图片或文件；图片保持 Obsidian 原生粘贴行为。
- 文本未超过自动处理字符上限（默认 30,000，可设置）。
- 光标不位于代码块、行内代码、YAML 或可识别的公式上下文。
- 启用的规则实际产生了修改，例如 `·` 列表、`1)` 序号、词典确认的断词或粘连词。普通无变化内容不弹窗。

自动粘贴只运行本地规则，不读取系统剪贴板图片。窗口显示 API 地址、模型与原文/图片；只有点击「发送并转换」或「使用 LLM 智能转换」后才发出 API 请求。

## 离线规则

设置中的离线规则列表统一管理「英文断词与粘连词」「列表与缩进」「连接普通段落硬换行」与自定义正则规则。所有规则按从上到下的顺序执行，可随时开关，拖动左侧三横杠或使用上下箭头调整顺序。内置规则不可编辑或删除；升级时保留原来的开关状态与默认执行顺序。

点击「新增规则」可添加自定义正则规则（初始关闭），填写名称、匹配表达式、替换文本和匹配标志，再开启规则。表达式使用 JavaScript 正则语法，不带两侧 `/`；默认标志 `g` 表示全部替换，可搭配 `i` 忽略大小写、`m` 多行或 `s` 跨行。替换文本支持 `$1` 等捕获组，留空表示删除。无效表达式会在设置中提示，并在执行时跳过。正则规则同样跳过代码、公式、链接等受保护内容，匹配不会跨越这些内容。

### 英文单词

- 内置英美英语拼写词典和词频，默认自动处理，无需自行提供词表；离线运行，不下载词典、不调用 API。
- `infor-\nmation` → `information`，`organi-\nsations` → `organisations`：支持词缀变化；仅在词典确认且不存在明显竞争解释时删除跨行连字符。
- `well-\nknown` → `well-known`：完整词组成的真实连字符表达，仅删除换行。`re-creation`、`re-\ncreation` 等有歧义的形式保留原文。
- `infor-mation` → `information`：删除词典确认的误插入连字符；两边都是完整词时保留。
- 软连字符 U+00AD 与其后的换行可直接还原。
- `ofthe` → `of the`，`neuralnetwork` → `neural network`，`Iam` → `I am`：对未知词尝试两词拆分，支持常见短词。候选须有词典与词频依据；多个候选得分接近时不修改。自动拆分只插入空格，不改字母。
- 已知完整词（如 `another`、`therapist`）、全大写缩写、混合大小写名称、标识符及带撇号的词不自动拆分。暂不拆分需要三个或更多词的连续字符串。
- 「额外词表」为可选补充，保留原有配置，可加入专业术语、品牌或姓名以防拆分。
- 「精确替换表」优先于自动拆分和完整词保护，可强制指定结果。即使清空两张自定义表，内置自动处理仍可使用。
- 词典和词频不能消除所有语义歧义；漏收的专业术语仍可能误拆，请检查差异预览，必要时加入额外词表或手动交给 LLM。

普通段落硬换行合并默认关闭，可在设置开启。代码、链接、YAML、已有 LaTeX 等语法会尽量保护；复杂 HTML、异常 Markdown 和缩进代码的识别并非完整语法解析，应用前应检查预览。

### 列表与缩进

支持 `• · ● ○ ◦ ▪ ▫ ‣ ⁃ ∙ – — −` 等无序列表，以及数字、字母、罗马序号。数字中的 `)`、`、`、全角点等转换为 `.`。

```text
· Parent
wrapped content
○ Child
child content
· Next parent
```

转换为：

```markdown
- Parent
  wrapped content
    - Child
      child content
- Next parent
```

优先保留原始缩进层级，并使用设置的子列表缩进（默认 4 空格）规范化。原始缩进相同时，新的行头符号推断为下一级；之前的符号再次出现时回到对应层级。续行与该列表项的**正文起始列**对齐，包括多位序号。空行后的普通段落结束续行缩进。

多行列表被复制成一段时，也会为确认的行中项目符号添加换行并还原层级。判断顺序如下：

1. 先保护代码、链接和公式，再还原词典确认的连字符断词，最后识别列表。`infor-mation`、`infor-\nmation` 中的连字符不会优先当成项目符号。
2. 空行、标题、引用、表格及受保护的独立代码/公式块划分识别范围，避免跨段落拼凑列表依据。
3. 优先根据原有行首符号与显式缩进确定层级；同一符号在相同原始缩进下复用层级。行中同类符号沿用这个结果；没有行首依据的新符号按首次出现顺序继续向下分层。
4. 没有行首依据的无序符号，须在同一范围内出现至少两次，且各次前后最近的**非空白字符组合**均不同，才作为列表。不能直接比较紧邻的空格，否则通常会把所有 ` • ` 判为相同上下文。`•` 等明显的点号允许与正文相连；`- / – / —` 允许紧接上一项正文（如 `attention:- the`、`states- attention`、`decoder:– At`、`yet)– At`），但符号后仍须有空白，并按上述重复与上下文规则确认。`+ * −` 须与正文以空白分开。数值范围、常见算术表达式、单词内部连字符和强调语法尽量保留。
5. 有序列表按「序号类型、分隔符、父编号前缀」分组。行中同组的相邻候选须为 `n`、`n+1`，才确认这两个候选；其间可以夹着其他格式的子列表。支持 `9) / 10)`、`a) / b)`、`i) / ii)`、`1、 / 2、` 等。孤立或不连续的行中序号不自动拆行。
6. `1.1`、`1.1.1`（也可带末尾的点）用完整前缀确定父子关系，输出各层的局部序号。连续子项可以反向确认父项，已确认的父项也可以确认单独的子项。不带末尾分隔符的多段数字须存在对应的父编号，避免把普通小数或版本号直接当作列表。单独的 `1.2 / 1.3` 没有父项依据时保留。
7. 无序与有序列表共用层级关系。子项至少缩进到父项正文起始列，避免设置为 2 空格时破坏多位序号的 Markdown 嵌套。已有 Markdown 的行尾硬换行空格及 CRLF 换行风格保留。

例如，下面这一段：

```text
简介 • infor-mation 1) First 2) Second • repre-sentation
```

转换为：

```markdown
简介
- information
    1. First
    2. Second
- representation
```

当源文本已丢失层级信息时，这种推断可能有歧义；例如同一种 `1)` 格式在一段内重启编号，无法唯一判断是否进入子列表。支持用不同编号格式、显式缩进或完整数字前缀提供层级依据；可在「差异 / 预览」视图的编辑区修正剩余歧义。字母 `i)` 等与罗马序号存在歧义，按常见罗马形式处理。

## API 配置

使用 `POST {Base URL}/chat/completions`，也接受完整的 `/chat/completions` URL。无需安装 OpenAI SDK。

设置分为「智能转换」和「图片转换」两个独立分区，各自填写：

- **Base URL**：兼容 OpenAI Chat Completions 的服务地址；本地 `localhost` 可使用 HTTP。
- **API Key**：服务的访问密钥，保存在 **Obsidian SecretStorage**，不写入插件 `data.json`。仍应按 Obsidian 自身的密钥存储和设备安全方式管理。
- **Model Name**：服务提供的准确模型名称或 ID，分别用于文本转换和图片识别。

统一入口下的文本 API 与视觉 API 仍使用独立配置，可使用不同服务、密钥和模型，修改或清除一个分区的密钥不会影响另一个。「智能转换」分区用于纯文本，「图片转换」分区用于含图片的输入。等待超时和补充格式要求放在「通用转换设置」中。

升级时，旧版独立供应商配置分别迁移至对应分区；上一版统一 API 配置会初始化两个分区，密钥自动复制到各自独立的 SecretStorage 条目。

图片使用标准 `image_url` content part 和 Base64 data URL；要求「图片转换」中所填模型支持此输入格式。支持 PNG、JPEG、WebP、GIF，插件限制为 10 MB，供应商可能有更严格限制。若模型不支持视觉，请在「图片转换」分区更换支持图片输入的模型和相应 API 配置。

模型提示词要求保留标题、列表、缩进、**加粗**、*斜体*、`==高亮==`、表格及公式；公式使用 `$...$` / `$$...$$`。识别正确率、文字格式和公式准确性受图片质量与模型影响，不保证逐像素还原。无法辨认的部分要求模型标为 `[无法辨认]`。

请求不设置强制温度或供应商特有参数，避免兼容性问题。不执行模型返回的工具调用或原文中的指令；API 返回文本原样保留，避免误删原有代码围栏。

### 数据与异步保护

- 离线规则不联网；手动 API 操作仅发送窗口中的文本、引用或添加的图片及转换指令，不发送整本笔记库。
- 使用 Obsidian `requestUrl`，避免普通浏览器 fetch 的 CORS 限制。
- 预览期间原文档变化、关闭或切换时阻止写入，保留结果以便复制。确认应用使用单次编辑替换，可撤销。
- 关闭窗口或超时停止等待，不再应用迟到响应。Obsidian `requestUrl` 不提供底层请求中断，供应商可能继续执行并计费。
- 不自动重试以避免重复请求和费用；错误提示不回显密钥或完整供应商错误正文。
- 排版预览由 Obsidian MarkdownRenderer 渲染，内容中的远程图片等可能在打开该页签时加载。

## 本地开发

需要 Node.js 22+：

```sh
npm ci
npm run check
npm run dev
```

`npm run build` 执行 TypeScript 检查并打包 `main.js`。`npm run release` 先测试与构建，再生成 `dist/easy-paste/`，可直接复制到笔记库。

源代码：

- `src/rules.ts`：纯函数规则与 Markdown 语法保护。
- `src/lists.ts`：行首/行中列表识别、连续编号确认及混合嵌套层级还原。
- `src/words.ts`：内置词典校验、保守断词还原与词频辅助拆分。
- `scripts/build-lexicon.mjs`：构建时打包词典与固定版本词频，无需联网；来源与校验值见 `data/README.md`。
- `src/api.ts`：可注入传输层的 OpenAI 兼容接口、取消与超时。
- `src/input.ts`：图片嵌入检测、输入校验与文本/视觉路由。
- `src/preview.ts`：统一文本/图片输入、可编辑差异、实时排版、规则侧栏和 LLM 入口。
- `src/rule-list.ts`：设置与预览共用的规则开关、拖动排序及键盘排序。
- `src/target.ts`：异步编辑目标保护。
- `src/main.ts`：Obsidian 事件与命令接入。
- `src/settings-tab.ts`：开关、规则表、供应商与密钥设置。

测试使用 Node test runner，API 请求全部使用 mock，不需要密钥。覆盖规则、请求格式、错误处理和异步写入保护，不代表已验证所有真实供应商或移动设备。
