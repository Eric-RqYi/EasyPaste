# 多语言词表维护

已提供 [`zh-CN.json`](zh-CN.json)、[`en.json`](en.json) 和 [`ko.json`](ko.json)，每份包含 177 个消息键。英语和韩语以用户确认的简中词表为依据，三个语言均可在插件设置中选择。

## 审阅方式

- 修改冒号右侧的显示文本，保留消息键。相似文案按使用场景分开，例如命令名称、设置分区名称和转换原因，以便后续分别调整。
- 保留 `{name}`、`{index}`、`{section}`、`{url}`、`{status}`、`{hint}`、`{error}` 等占位符及名称，可以调整位置。它们在运行时填入规则名称、序号、地址或具体原因，不能直接改成某个固定值。
- 遵守 JSON 转义：说明中要显示字面 `\n` 时，JSON 中写 `\\n`；不要将这些说明文字改成实际换行。API 字段名、格式名称、示例地址也保留在词表中，可按需要调整展示用语。
- 用户输入的正文、转换结果、图片文件名、自定义规则名称、正则内容、词汇表、已保存的 Prompt 和临时要求属于用户数据，切换界面语言时保留原文。未改名的内置示例规则按词表展示；改名后按用户内容展示。示例默认名在配置中按空名称保存并按稳定规则 ID 显示，避免简中文案调整后失去语言关联；旧默认名称通过 `../legacy-rule-names.json` 中的固定迁移数据识别。旧配置中已保存的其他名称不批量翻译。

还检查了 `styles.css`：没有由 CSS 生成的用户文案。`lists.ts`、`words.ts`、`spelling.ts`、`context.ts` 不生成界面消息。静态插件元数据 `manifest.json` 由 Obsidian 读取，不属于插件内部语言设置可动态切换的界面。

`../default-prompts.json` 是可编辑模型指令的初始配置，不随界面语言替换，也不把已有英文指令自动改写为简中；这样保留用户已调整的模型行为。Prompt 编辑按钮、说明和辅助阅读标签均已收进词表。Obsidian 自身的关闭控件、原生文件选择器等跟随宿主 / 系统语言。

## 框架与词表同步

翻译工具位于 [`../i18n.ts`](../i18n.ts)：语言归一化、消息键类型、命名参数插值、逐条简中回退、词表完整性与占位符检查，以及带消息键的用户错误。

三个词表均已登记到 `i18n.ts` 的 `catalogs`。修改消息后，应同步维护三个文件的键名和占位符；`npm run check` 会核对词表一致性、插值、真实语言切换与配置重载。语言选项仅在词表完整时启用，`language.pending` 只作为词表不完整时的状态文案。

用户在简中词表中注释的 `language.description` 和 `preview.rulesUpdated` 已连同对应显示代码删除；原消息使用的 `reason.separator` 已无用途，也已移除。规则更新继续重算结果并更新原因标签，有变化时清空旧状态消息，无变化时仍显示 `preview.rulesUnchanged`。JSON 文件保留为标准 JSON，不保留已删除条目的注释。

语言设置持久化到 `data.json` 的 `language` 字段，默认 `zh-CN`；非法值回退到简中。暂缺词表的已保存语言使用简中消息回退。设置切换后重绘，命令和菜单读取当前语言；预览持有打开时的翻译器，避免切换语言导致当前编辑丢失或请求被重建。
